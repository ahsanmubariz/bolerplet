# R-006 session
- Date: 2026-10-05
- Pinned versions: fiber v3.5.0, go 1.27.1 (toolchain), gofiber/utils/v2 v2.4.1, fasthttp v1.73.0, github.com/gofiber/storage/postgres/v3 v3.7.1 (latest; versions …v3.6.2, v3.7.0, v3.7.1), github.com/jackc/pgx/v5 v5.11.0 (required by the adapter)
- Question: `New` vs `NewStore` vs `NewWithStore`; how a handler gets the session; Regenerate/Destroy/Reset/Release/Save semantics and when Release is required; IdleTimeout/AbsoluteTimeout; cookie option names; `__Host-` compatibility; KeyGenerator default; the v3 `fiber.Storage` interface; whether `gofiber/storage/postgres/v3@v3.7.1` implements it, plus its config, pgx version, and whether it auto-creates its table (DDL vs DML role, BASELINE §7).

- Findings (facts only):
  - **Constructors**:
    - `session.New(config ...Config) fiber.Handler` is middleware only; the store is discarded.
    - `session.NewWithStore(config ...Config) (fiber.Handler, *Store)` returns middleware plus the `*Store` (needed for csrf `Session:` and for `store.Delete(ctx,id)` / `GetByID`). If `cfg.Store == nil` it calls `NewStore(cfg)`.
    - `session.NewStore(config ...Config) *Store` is store-only. `Storage == nil` falls back to the in-memory store.
  - **Handler access (middleware mode)**: `session.FromContext(c) *Middleware`, which returns nil if the middleware did not run (e.g. routes mounted before it, or `Next` skipped). `*Middleware` methods: `Get/Set/Delete/Keys/ID/Fresh/Destroy/DestroyWithContext/Regenerate/RegenerateWithContext/Reset/ResetWithContext/Store`. There is **no Save/Release in middleware mode**: after `c.Next()` the middleware always calls `saveSession()` and releases the session, unless `Destroy` was called, in which case it only releases.
  - **Store mode**: `store.Get(c) (*Session, error)` returns `ErrSessionAlreadyLoadedByMiddleware` if the middleware already loaded the session for this request (spike-proven). In store mode the caller MUST call `sess.Save()` to persist and `sess.Release()` (returns the object to a sync.Pool) when done. The same applies to `store.GetByID(ctx,id)`. `Session.Save()` is a no-op when the session is the middleware-owned one.
  - **Middleware saves on every request.** Even a handler that never touches the session gets a new ID, a stored (empty) row, and a `Set-Cookie` (spike-proven). Each request also re-sets the cookie and upserts the row, which slides `IdleTimeout`. If the save fails, `ErrorHandler` (default `DefaultErrorHandler`: log plus 500 "Internal Server Error") runs **after** the handler.
  - **Semantics** (session.go):
    - `Regenerate()`: storage `Delete(oldID)`, then `id = KeyGenerator()`, `isFresh = true`. **Data is kept** (including the hidden absolute-expiry key). The new ID is saved and the cookie set by the middleware after the handler.
    - `Reset()`: storage `Delete(oldID)`, clears all data, `idleTimeout = 0`, sets an expired cookie, then a new ID. The middleware then saves the new empty session and overwrites the cookie with the new ID.
    - `Destroy()`: storage `Delete(id)`, clears data, sets an expiring cookie (`max-age=0` with the same Path/Secure/HttpOnly/SameSite attributes). The middleware marks it destroyed and does **not** re-save. The next request gets a fresh session.
    - `Release()`: returns the object to the pool. Only for store-mode / `GetByID` sessions.
    - `Save()`: encodes data (gob), `Storage.SetWithContext(id, bytes, idleTimeout)`, and sets the cookie.
  - **Unknown or old IDs are never adopted.** If `Storage.Get(id)` returns nil, a new ID is generated (no fixation), proven with an attacker-chosen cookie and with the pre-Regenerate ID.
  - **Timeouts**: `IdleTimeout` defaults to 30m (`<= 0` → 30m). `AbsoluteTimeout` defaults to 0 (off) and panics if `0 < Absolute < Idle`. It is **store-wide**; a per-session override exists only for idle (`Session.SetIdleTimeout`). The absolute deadline is stored as a hidden data key (unexported type) set only when `getSession` creates a fresh session. When it passes, `getSession` calls `Reset()` (new ID, data cleared) and sets a new deadline. **Regenerate keeps the original deadline** (counted from the first anonymous request). **A user-called `Reset()` removes the deadline and nothing re-adds it, so that session never expires absolutely** (spike-proven: a normal session rotated after `AbsoluteTimeout` = 3s while a Reset session kept its ID for 4s+).
  - **Cookie options**: there is **no `CookieName` field**. The name comes from `Extractor` (default `extractors.FromCookie("session_id")`). Fields: `CookieDomain` (""), `CookiePath` (""), `CookieSameSite` ("Lax"; "Strict"/"None" accepted, None forces Secure), `CookieSecure` (false), `CookieHTTPOnly` (false), `CookieSessionOnly` (false, which means `Max-Age = IdleTimeout` and Expires are set). Other fields: `Storage fiber.Storage`, `Store *Store`, `Next`, `ErrorHandler func(fiber.Ctx, error)`, `KeyGenerator func() string`, `IdleTimeout`, `AbsoluteTimeout`. If the Extractor is a header source, the ID is echoed in a response header instead.
  - **`__Host-` works** with `Extractor: extractors.FromCookie("__Host-sid")`, `CookiePath: "/"`, `CookieSecure: true`, `CookieDomain: ""`. Neither Fiber nor fasthttp *enforces* the prefix rules (no `__Host-` handling in the source), so correctness depends on our config. Observed: `__Host-sid=<43 chars>; max-age=1800; path=/; HttpOnly; secure; SameSite=Lax`. fasthttp writes `path=/` even when `CookiePath` is "" (spike), but we set it explicitly. The deletion cookie keeps `path=/; HttpOnly; secure`.
  - **KeyGenerator default** `utils.SecureToken`: 32 bytes from `crypto/rand` (panics on failure), base64url without padding, 43 chars. The session ID is an opaque random value: no signing, no `SESSION_KEY` used anywhere.
  - **Storage interface** (`fiber.Storage`, storage_interface.go): `GetWithContext(ctx,key) ([]byte,error)`, `Get`, `SetWithContext(ctx,key,val,exp)`, `Set`, `DeleteWithContext(ctx,key)`, `Delete`, `ResetWithContext(ctx)`, `Reset`, `Close`. Get returns `nil, nil` if the key is missing; empty key or value is ignored. The session uses the `*WithContext` variants with `c` as ctx.
  - **Postgres adapter** `github.com/gofiber/storage/postgres/v3` v3.7.1: `var _ fiber.Storage = (*postgres.Storage)(nil)` **compiles**. Its go.mod has `go 1.26.0` and requires `github.com/jackc/pgx/v5 v5.11.0` (MVS floor for our pgx pin; testcontainers deps are test-only and do not enter our build list).
    - Constructors: `New(...Config)`, `NewWithContext(ctx, ...Config)`, `NewFromConnection(*pgxpool.Pool, ...Config)`, `NewFromConnectionWithContext(ctx, *pgxpool.Pool, ...Config)`. All **panic** on error (no error return). Also `Conn() *pgxpool.Pool`, `Close()` (does not close an injected pool), `ErrClosed`.
    - Config: `DB *pgxpool.Pool` (injection; overrides URI/host fields), `ConnectionURI`, `Host` (127.0.0.1), `Port` (5432), `Username`, `Password`, `Database` ("fiber"), `Table` ("fiber_storage"; `schema.table` allowed, quoted with `pgx.Identifier`), `SSLMode` ("disable", ignored when `DB` is injected), `Reset` (false; **`DROP TABLE`** on start), `Unlogged` (false), `GCInterval` (10s; runs `DELETE … WHERE e <= now AND e != 0` per instance).
    - **Auto-DDL**: at construction it pings, checks `information_schema.tables`. **If the table is missing it runs `CREATE TABLE` and `CREATE INDEX`** (DDL). If the table exists it runs no DDL, except `ALTER COLUMN k TYPE TEXT` when `k` is `character varying`. It then validates columns `k text`, `v bytea`, `e bigint` and panics on mismatch. The index is created only together with the table. Runtime SQL: `SELECT v,e … WHERE k=$1`, `INSERT … ON CONFLICT (k) DO UPDATE`, `DELETE … WHERE k=$1`, GC `DELETE`, and `TRUNCATE` (only via `Storage.Reset`/`store.Reset`).
    - Keys are stored **in plaintext** (`k` = session ID). Anyone with read access to the table can hijack sessions.
- Decision / impact on BASELINE.md:
  - §1: Session/limiter storage is `github.com/gofiber/storage/postgres/v3` **v3.7.1**, built with `NewFromConnection(appPool, postgres.Config{Table: "sessions", GCInterval: time.Minute})`.
  - §7: the storage table is created by a **goose migration** (DDL role): `CREATE TABLE sessions (k TEXT PRIMARY KEY NOT NULL DEFAULT '', v BYTEA NOT NULL, e BIGINT NOT NULL DEFAULT 0); CREATE INDEX sessions_e_idx ON sessions (e);`. The app role gets only `SELECT, INSERT, UPDATE, DELETE`. Never set `Reset: true`; never call `store.Reset`. Construction panics, so wrap it in boot with recover → error.
  - §6.2 wiring: `session.NewWithStore(session.Config{Storage: pg, Extractor: extractors.FromCookie("__Host-sid"), CookiePath: "/", CookieSecure: true, CookieHTTPOnly: true, CookieSameSite: "Lax", IdleTimeout: 30*time.Minute, AbsoluteTimeout: 12*time.Hour, ErrorHandler: <log + 500 via httpx>})`. Handlers use `session.FromContext(c)` (nil-check).
  - §6.2 rotation: login and privilege/password change use `Regenerate()` (old row deleted; data kept, so set `uid`/`auth_time` after it). **Logout uses `Destroy()`, not `Regenerate()`** (Regenerate keeps `uid`). Avoid `Reset()` on authenticated flows because it drops the absolute deadline.
  - §6.2 timeouts: Fiber's `AbsoluteTimeout` is store-wide and counts from session creation, not login. The 12h/8h-admin absolute limits must be enforced by the auth loader from the stored `auth_time` (Destroy plus redirect to login when exceeded). Fiber's `AbsoluteTimeout: 12h` stays as a backstop.
  - §6.11: `SESSION_KEY` has no consumer (IDs are opaque random tokens; Fiber does not sign them). Drop it, or (ADR) use it to key a thin storage wrapper that stores `HMAC-SHA256(SESSION_KEY, id)` instead of the plaintext ID.
  - §5: because the middleware persists a row and sets a cookie on **every** request that reaches it, the static-before-session and limiter-before-session order is load-bearing. Consider `Next` to skip `/healthz` and similar endpoints.
  - R-007 note: Regenerate keeps all data, so a session-stored CSRF token survives login unless csrf rotates it.
