- Findings (facts only):
  - **Config fields and defaults (v3.5.0).** `ConfigDefault = {CookieName: "csrf_", CookieSameSite: "Lax", IdleTimeout: 30m, KeyGenerator: utils.SecureToken, ErrorHandler: defaultErrorHandler (returns fiber.ErrForbidden → 403), Extractor: extractors.FromHeader("X-Csrf-Token"), DisableValueRedaction: false}`. Other fields and zero-value defaults: `Storage fiber.Storage` (memory; ignored if Session set), `Next func(fiber.Ctx) bool`, `Session *session.Store`, `CookieDomain ""`, `CookiePath ""` (→ `DefaultRes.Cookie` rewrites empty Path to `/`), `TrustedOrigins []string` (supports `https://*.example.com`, any depth; invalid entry → panic at `New`), `CookieSecure false`, `CookieHTTPOnly false`, `CookieSessionOnly false`, `SingleUseToken false`. Exported const `csrf.HeaderName = "X-Csrf-Token"`. There is **no** `Expiration`, `CookieExpires` or `ContextKey` field. `configDefault` fills only IdleTimeout(≤0), CookieName, CookieSameSite, KeyGenerator, ErrorHandler, Extractor — CookieSecure/HTTPOnly must be set explicitly.
  - **Session mode.** With `Session: store` the token is stored in the session under an unexported key (`sessionKeyType(0)`) as `csrf.Token{Key, Raw:"+", Expiration: now+IdleTimeout}`; only **one** token per session. `New` calls `store.RegisterType(sessionKeyType(0))` and `store.RegisterType(Token{})`. Lookup uses `session.FromContext(c)` (session *middleware*) if present, else falls back to `store.Get(c)` + `Save()` + `Release()` itself. **A cookie is still set**: the token value is written to the CSRF cookie on every request that passes through (GET and successful unsafe), and on unsafe methods the extracted token must **equal the cookie value** (constant-time double-submit check) **and** match the session's token. So session mode = double-submit cookie + synchronizer token. Spike `Set-Cookie`: `__Host-csrf=…; expires=…+30m; path=/; HttpOnly; secure; SameSite=Lax`.
  - Every GET through csrf writes/extends the token in the session → **every anonymous page view creates (and re-saves) a server-side session** (`__Host-sid` issued on first GET in the spike).
  - Safe methods (no check, token issued/extended): GET, HEAD, OPTIONS, TRACE, QUERY. Everything else is checked.
  - On a GET, if the cookie token does not match the session token, a **new** token is generated (silently replaces the session's token).
  - In session mode, session read errors are swallowed and become `ErrTokenNotFound` (fail closed); session write errors in fallback mode are only `log.Warn`ed.
  - **Unsafe-method check order** (`csrf.go` L139–207): (1) `validateSecFetchSite` → (2) Origin check → (3) if Origin absent/`null`: Referer check **only when `c.Scheme()=="https"`**, skipped on http → (4) `Extractor.Extract` → (5) extracted == cookie → (6) token present/unexpired in session (mismatch also expires the cookie) → (7) if SingleUseToken delete + issue new, else extend.
  - **Errors passed to ErrorHandler** (all exported `var`s, use `errors.Is`): `ErrTokenNotFound` (no token extracted, or not in this session/expired), `ErrTokenInvalid` (extracted ≠ cookie), `ErrFetchSiteInvalid`, `ErrRefererNotFound`, `ErrRefererInvalid`, `ErrRefererNoMatch`, `ErrOriginInvalid` (unparseable or duplicate Origin), `ErrOriginNoMatch`. Also possible: non-`ErrNotFound` extractor errors (e.g. `extractors.ErrChainCycle`) and, in Storage mode only, wrapped `"csrf: failed to … storage: %w"` errors. `DeleteToken` returns `ErrTokenNotFound` via ErrorHandler when no cookie.
  - **ErrorHandler signature:** `fiber.ErrorHandler` = `func(fiber.Ctx, error) error`.
  - **Sec-Fetch-Site:** accepted values (case-insensitive, trimmed): `same-origin`, `none`, `cross-site`, `same-site`; absent or empty → skipped; any other value or the header sent more than once → `ErrFetchSiteInvalid`. **`cross-site` is NOT rejected by itself** (source comment: it is legitimate for TrustedOrigins); cross-site rejection relies on the Origin/Referer check. Origin must match `c.Scheme()+c.Host()` (scheme-sensitive: `http://host` on an https request → `ErrOriginNoMatch`) or a TrustedOrigin. `Origin: null` is treated as absent. Origin/Referer/Sec-Fetch-Site are read case-insensitively and a duplicated header is refused.
  - **Referrer-Policy interaction (important).** helmet v3.5.0 default `ReferrerPolicy: "no-referrer"`. Per the Fetch spec, a non-CORS-mode request (i.e. a plain HTML `<form method=post>` navigation) whose referrer policy is `no-referrer` sends `Origin: null`, and no Referer is sent. On HTTPS, Fiber csrf then requires a Referer → `ErrRefererNotFound` → **every plain form POST is rejected in production**. htmx/fetch (CORS mode) still send a real Origin. Spike case "https real browser form POST under no-referrer" proves the server side (403). The stdlib `CrossOriginProtection` would accept the same request (it trusts `Sec-Fetch-Site: same-origin` first). With `Referrer-Policy: same-origin` or `strict-origin-when-cross-origin`, a same-origin HTTPS POST keeps its real Origin.
  - **Extractors package** (`github.com/gofiber/fiber/v3/extractors`): `FromHeader`, `FromAuthHeader`, `FromForm`, `FromQuery`, `FromParam`, `FromCookie`, `FromCustom(key, fn)`, `Chain(...)`; `type Extractor{Extract, Key, AuthScheme, Chain, Source}`, `(Extractor) Contains(pred)`, `Source` consts (`SourceHeader…SourceCustom`), `ErrNotFound`, `ErrChainCycle`. `Chain` returns the first non-empty value in order; metadata (`Source`/`Key`) of the first element. `FromForm` uses `c.FormValue` (urlencoded and multipart).
  - **Security validation:** `validateExtractorSecurity` (in `configDefault`, so at `csrf.New`) **panics only if** the extractor or any element of its chain (recursively, via `Contains`) is `SourceCookie` with `Key == CookieName` exactly; case-insensitive look-alike only warns; Query/Param primary source only warns. `extractors.Chain(extractors.FromForm("_csrf"), extractors.FromHeader("X-Csrf-Token"))` **passes** (spike). A nested `Chain(..., Chain(..., FromCookie("__Host-csrf")))` panics (spike). Note: `FromCustom` reading the cookie is not detected.
  - **Context helpers:** `csrf.TokenFromContext(ctx any) string` and `csrf.HandlerFromContext(ctx any) *csrf.Handler` (accept fiber.Ctx, CustomCtx, *fasthttp.RequestCtx, context.Context). Values are stored with `fiber.StoreInContext` → Locals always, `c.Context()` only if `Config.PassLocalsToContext` is true. Token is set in context for GET and for successful unsafe requests (with SingleUseToken it is the *new* token).
  - **Rotation:** `(*csrf.Handler).DeleteToken(c fiber.Ctx) error` deletes the token from the session and expires the cookie (replaces the earlier Set-Cookie in the same response). `session.Regenerate()` keeps session data, so **the pre-login CSRF token survives login** unless deleted (spike: 200 with Regenerate only; 403 with Regenerate + DeleteToken). `session.Reset()`/`Destroy()` wipe data, so the token goes with them.
  - **SingleUseToken:** after a valid unsafe request the token is deleted and a new one issued (new cookie). Any other open tab, a page with several forms/htmx triggers, a back-button resubmit, or a double-click retry then fails (`ErrTokenInvalid`, because the cookie now holds the new token). With htmx every response would have to OOB-update `hx-headers` and all forms. Benefit is marginal for a synchronizer token already bound to the session and rotated on login.
  - **PR #4596** (author RubenPari, opened 2026-08-09): **open, not merged**, not in v3.5.0 (`CrossOriginProtection` does not appear in the v3.5.0 source). As of 2026-09-28: unresolved review threads, merge conflicts reported, maintainers debating a separate middleware; author proposed replacing the flag with `csrf.NewCrossOriginProtection(csrf.CrossOriginConfig{Next, ErrorHandler, TrustedOrigins})`. API not stable.
  - **`net/http.CrossOriginProtection`** (go1.27.1): `NewCrossOriginProtection()`, `AddTrustedOrigin`, `AddInsecureBypassPattern`, `SetDenyHandler`, `Check(*http.Request) error`, `Handler(http.Handler)`. Safe = GET/HEAD/OPTIONS. `Sec-Fetch-Site`: `same-origin`/`none` → allow; any other non-empty value (incl. `same-site`, `cross-site`, garbage) → reject unless trusted/bypassed; absent → compare Origin host with Host (scheme ignored); neither header → allow. Tokenless, no cookie. It is a `net/http` type; with Fiber (fasthttp) it can be used only via `adaptor` or by building a minimal `*http.Request{Method, Host, Header, URL}` and calling `Check` (spike `TestR007_StdlibCrossOriginProtection` does this in ~10 lines).
- Decision / impact on BASELINE.md:
  - Keep Fiber csrf in session mode as specified. Config: `Session: store` (same store as session middleware, created with `session.NewWithStore`), `Extractor: extractors.Chain(extractors.FromForm("_csrf"), extractors.FromHeader(csrf.HeaderName))`, `CookieName: "__Host-csrf"`, `CookieSecure: true`, `CookieHTTPOnly: true`, `CookieSameSite: "Lax"`, `CookiePath: "/"`, `CookieDomain: ""`, `IdleTimeout: 30*time.Minute`, `SingleUseToken: false`, `TrustedOrigins: nil`, custom `ErrorHandler` that maps the exported errors to a `reason` attribute for `csrf.rejected` and renders the 403 page.
  - Session middleware MUST run before csrf (already #8 → #9).
  - Change helmet `ReferrerPolicy` from `no-referrer` to `same-origin` (otherwise all HTTPS form POSTs fail). Lock in with a test.
  - Rotate the CSRF token on login/logout/privilege change: `csrf.HandlerFromContext(c).DeleteToken(c)` after `Regenerate()` (or use `Reset()`).
  - Do not adopt PR #4596 (unmerged, API in flux). Do not add `net/http.CrossOriginProtection` now: Fiber csrf already does Origin/Referer + token; re-evaluate when #4596 or a successor ships.
  - BASELINE test "malformed Sec-Fetch-Site → 403" holds; add "cross-site with foreign Origin → 403" (by Origin check), and note `cross-site` alone is not a rejection reason.
  - Anonymous GETs create sessions (storage growth); acceptable with the global limiter, but session storage GC must exist (R-006).
  - Pass the token to templates via `csrf.TokenFromContext(c)` with the fiber.Ctx, not `c.Context()` (works only with `PassLocalsToContext`).
